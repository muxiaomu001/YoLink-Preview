# 界面文案与名词规范

适用范围：客户手机端、客服工作台、管理后台三端全部界面文字，包括标题、按钮、字段名、占位符、提示条、弹窗、Toast、空状态、错误信息。

这份文件是界面文字的唯一标准。改任何界面文案前先读这里；这里没定的，按「第一节 三条底线」判断。

---

## 一、三条底线

1. **界面上的每一句话都是说给用户听的。** 不是说给产品听的，不是说给技术听的，不是替 PRD 做记录的。
2. **产品不解释自己的实现。** 用户要知道"能不能做、做了会怎样"，不需要知道"系统怎么实现的、记了什么日志、对应哪个权限键"。
3. **凡是要对看演示的人解释的话，一律进演示批注层**（见第五节），不能混在产品文案里。

### 界面上绝对不能出现的内容

| 类型 | 反面例子 | 为什么 |
|---|---|---|
| 内部权限键、字段名 | `wallet.withdraw`、`ai.group_warmup`、`account.edit_profile`、「对应权限：adjust」 | 泄漏内部实现，用户看不懂，还给外部攻击者提供信息 |
| 排期标记写进文案 | `导出（P1）`、`钱包（P2）` | 排期是内部信息。要标排期走批注层的徽章，不写进标题字符串 |
| 会议记录、待决事项 | 「用户 2026-09-15 决定推到 P2」「规则待产品确认」「讨论稿」 | 内部过程，用户完全不关心 |
| 审计与留存机制 | 「记审计日志」「原文保留审计」「写入运行记录」 | 对客户说这个等于提醒他被监控；对员工可以说，但要换成人话 |
| 内部岗位口径 | 「按实操员工算」「按主归属坐席算」「老板看的六个数」 | 内部统计口径，不是给看的人理解页面用的 |
| 演示环境的妥协 | 「演示用色板代替上传」「正式版支持拖动，演示用上移/下移」 | 这是演示说明，进批注层，不进产品文案 |

### 内部信息的分级

同一件事，对不同人说法不同：

- **对客户（手机端）**：只说结果和影响。删除消息只说「对方仍然看得到」，不说企业留了副本。
- **对员工（工作台）**：可以说内部事实，但用人话。「删除不影响企业留存的会话记录」可以，「原文保留审计」不行。
- **对管理员（管理后台）**：可以说管理口径和规则，但仍然不出现权限键名和排期标记。

## 二、名词对照表

同一个动作、同一个对象，三端只能有一个叫法。左边是标准写法，右边是不能再用的写法。

### 消息动作

| 标准 | 不再使用 | 说明 |
|---|---|---|
| 回复 | 引用 | 针对某条消息作答。输入框上方的条也叫「回复」 |
| 回复并引用所选 | 引用所选文字 | 选中部分文字后回复，只带走选中那段 |
| 复制 | 拷贝、拷贝文本 | 成功提示统一「已复制」 |
| 转发 | 分享、转送 | |
| 编辑 | 修改消息 | 操作项叫「编辑」，弹窗标题可以叫「编辑消息」 |
| 删除 | 撤回、撤销 | 产品只有删除，没有撤回。范围（仅自己 / 为所有人）在删除弹窗里选 |
| 置顶 | 固定、pin | |
| 选择多条 | 多选、批量选择 | |

### 消息状态

| 标准 | 呈现方式 | 说明 |
|---|---|---|
| 发送中 | 时钟图标 + 文字 | |
| 发送失败 · 重试 | 警告图标 + 文字，可点 | 失败原因放 hover 提示，不占正文 |
| 已送达 | **单个对勾图标，不写字** | 1v1 里对方还没看 |
| 已读 | **双对勾图标 + 品牌色，不写字** | 1v1 里对方已看。文字放 hover 提示 |
| N/M 人已读 | 文字，可点开名单 | 群聊专用。这是企业功能，写出来是对的 |
| 已编辑 | 文字，灰色小字 | |

1v1 聊天里不要把「已读」「未读」两个字写在消息下面——主流聊天软件都不这么做，界面会碎。群聊的人数回执是另一回事，保留。

### 群发统计（与聊天回执不是一回事）

| 标准 | 说明 |
|---|---|
| 送达 | 成功推送到的人数 |
| 已读 | 打开看过的人数 |
| 跳过 | 因频控、屏蔽等原因没发的人数 |

群发页的这三个词是统计口径，**不要复用聊天回执的对勾图标**，避免两套语义撞车。

### 人与角色

| 标准 | 不再使用 | 说明 |
|---|---|---|
| 官方联系人 | 坐席（对客户说时） | 客户端一律叫「官方联系人」，客户不知道「坐席」是什么 |
| 坐席 | 客服号、账号 | 企业内部（工作台、管理后台）用「坐席」 |
| 实操员工 | 操作人、真人 | 内部概念，只在工作台和管理后台出现，客户端绝不出现 |
| 客户 | 用户、会员 | |
| 管理员 | 老板、超管 | |

### 会话对象

| 标准 | 不再使用 |
|---|---|
| 会话 | 对话、聊天窗口 |
| 群 | 群组、群聊（正式名用「群」，「群聊」可作口语出现在句子里） |
| 频道 | 广播、订阅号 |
| 话术库 | 快捷回复库、常用语 |

## 三、语气与句式

1. **按钮用动词，不超过 4 个字。** 「保存」「删除」「发送」「新建条目」。不要「点击这里保存」。
2. **提示说影响，不说机制。** 「对方仍然看得到这条消息」而不是「仅设置 hiddenFor 字段」。
3. **限制说清楚能做什么，不只说不能做什么。** 「发送超过 2 分钟后只能从你这边删除」优于「超时，禁止为所有人删除」。
4. **时长说人话。** 「2 分钟」「1 小时」「3 天」，不写「120 秒」。
5. **错误提示要能让用户下一步知道做什么。** 「网络已断开，请联网后重试」优于「发送失败」。
6. **不用感叹号，不用「哦」「呢」「啦」。** 企业产品，克制。
7. **数字与中文之间加空格**：`最多 5 台设备`。中文标点用全角，英文和数字用半角。
8. **不出现「暂无数据」这类空话。** 空状态说明白为什么空、怎么才能有：「还没有客户加入，先去邀请链接页生成一条链接」。

## 四、交互范式

自创交互等于给技术团队挖坑。以下按主流聊天软件的既定做法执行。

### 消息操作菜单

| 端 | 触发方式 | 菜单形态 |
|---|---|---|
| 客户手机端 | **长按消息**（桌面浏览器里同时支持右键） | 贴着消息的浮层菜单 |
| 客服工作台 | **悬停出现「···」按钮，或右键消息** | 定位在光标处的下拉菜单 |

- 手机端**不要**在每条消息旁常驻「···」按钮——没有任何主流聊天软件这么做。
- 手机端**不要**把单击绑定成弹菜单，单击要留给图片预览、引用条跳转、链接点击。
- 两端菜单条目和顺序保持一致：回复 / 复制 / 转发 / 编辑（仅自己发的）/ 置顶（仅群）/ 选择多条 / 删除。不适用的项直接不出现，不置灰。

### 删除

只有一个删除入口。范围在弹窗里选：

- 「仅为我删除」——本方视图移除，其他人不受影响。
- 「同时为对方删除」/「同时为群内所有人删除」——受时限和权限约束，不满足时那一项置灰并说明原因。

不做单独的「撤回」入口，避免和删除语义重叠。

## 五、演示批注层

演示要替 PRD 说话，所以界面上会有一些"说给看演示的人听"的内容。这些内容**必须和产品文案物理分离**，否则技术团队分不清哪句该照做、哪句该忽略。

### 规则

1. 所有演示批注只能通过 `src/ui/DemoNote.tsx` 里的组件输出：

   | 形式 | 用在哪 | 长什么样 |
   | --- | --- | --- |
   | `<DemoNote>` | 页面或区块级的旁白 | 灰底虚线块，左上角「演示说明」标签 |
   | `<DemoNote compact>` | 卡片内、手机屏里的短旁白 | 同上，字号更小 |
   | `<DemoHint>`（手机端 `parts.tsx`） | 手机屏内的旁白 | 转发给 `<DemoNote compact>` |
   | `<DemoLevelTag level="P1" />` | 标题、菜单项、字段名旁 | 虚线小徽章 |
   | `<LevelTag level="P1" />`（手机端 `parts.tsx`） | 手机屏内的排期标记 | 同上 |
   | `<Field demoHint="…">` | 表单字段下方 | 虚线小条，跟在输入框后面 |
   | `demoToast('改头像')` | 演示环境做不了的操作 | 「改头像在演示里不做实际改动」 |
   | `nav.ts` 的 `demoOnly: true` | 演示专属页面的导航项 | 关掉批注后整项消失 |

2. 产品自己的提示走正常组件：`PageHeader` 的 `desc`、`Note`、`Field` 的 `hint`、`toast(...)`。这些地方写的每一个字都要按第一到第三节的标准，当成正式产品来写。

   判断标准很简单：**这句话如果出现在客户已经买单、正在用的系统里，读起来奇不奇怪？** 「正式版支持拖动，演示用上移 / 下移」「待产品确认」「15 文档口径」这类话一律进批注层。

3. 演示批注有全局开关（首页、工作台演示浮条、管理后台顶栏各有一个）。**关掉开关后，三端就是正式产品应有的样子**，不多一个字、不多一个入口。
4. 排期标记（P0/P1/P2）只能用徽章组件渲染，不能写进标题、标签、字段名的字符串里。
5. 演示外壳（首页、工作台右下的演示浮条、手机屏右侧的演示控制面板）不受开关控制 —— 开关本身在那里面。它们整体不属于产品，交付时连同文件一起删。

### 交给技术团队时

1. 删掉 `src/ui/DemoNote.tsx`；同时删掉 `src/ui/DemoPendingModule.tsx` 及 `/admin/ai`、`/workbench/bots` 路由与导航项。
2. 全局搜 `DemoNote` / `DemoLevelTag` / `DemoNoteToggle` / `demoToast` / `DemoHint` / `LevelTag` / `demoHint` / `demoOnly`，删掉这些引用和被它们包住的内容；
3. 删掉演示外壳：`src/apps/landing/`、`src/apps/workbench/components/layout/DemoBar.tsx`、`src/apps/phone/DemoPanel.tsx`、`src/apps/admin/pages/DemoDataPage.tsx` 及其路由与导航项。

剩下的界面就是正式产品应有的样子。批注层不牵扯任何业务逻辑，删除不影响功能。

## 六、改文案时的自检

- [ ] 这句话是说给用户听的，不是说给产品或技术听的
- [ ] 没有权限键名、字段名、排期标记、会议记录
- [ ] 名词在第二节的表里能查到，且用的是标准写法
- [ ] 对客户 / 对员工 / 对管理员的分级说法没有说错对象
- [ ] 演示说明进了批注层，没有混在产品文案里
- [ ] 交互没有自创，按第四节的范式
